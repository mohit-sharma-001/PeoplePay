PEOPLEPAY360 BACKEND - COMPLETE STEP-BY-STEP API & FEATURE TESTING GUIDE

-------------------------------------------------------------------------------
PREREQUISITES: ENVIRONMENT & SERVER STARTUP COMMANDS
-------------------------------------------------------------------------------
1. Check PostgreSQL Database Service (ensure DB 'peoplepay360_db' is running):
   pg_isready -h localhost -p 5432

2. Activate Python Virtual Environment:
   source venv/bin/activate

3. Start Django REST API Development Server:
   python manage.py runserver

* Note: Default API server runs at http://127.0.0.1:8000/

STEP 0: CREATE NEW ADMIN USER
-------------------------------------------------------------------------------
FEATURE TESTED:
User Account Provisioning & Role-Based Access Control (RBAC). Grants Django
superuser/staff permissions and assigns the user to the 'Admin' RBAC Group.

RUNNING COMMAND (Option A - Interactive):
python manage.py createsuperuser --username admin --email admin@peoplepay360.com

RUNNING COMMAND (Option B - Non-Interactive One-Liner):
python manage.py shell -c "from django.contrib.auth.models import User, Group; u, _ = User.objects.get_or_create(username='admin', defaults={'email':'admin@peoplepay360.com', 'is_superuser':True, 'is_staff':True}); u.set_password('admin123'); u.save(); g, _ = Group.objects.get_or_create(name='Admin'); u.groups.add(g)"

STEP 1: ADMIN LOGIN & TOKEN AUTHENTICATION
-------------------------------------------------------------------------------
FEATURE TESTED:
Token-Based Authentication Endpoint (/api/auth/login/). Authenticates user credentials,
generates Django REST Framework Auth Token, and retrieves assigned RBAC roles.

STEP 8: TEST FORGOTTEN CHECK-OUT / OVERTIME SAFETY CAP (>14 HOURS)
-------------------------------------------------------------------------------
FEATURE TESTED:
Automated Forgotten Check-Out Protection. If an employee forgets to check out
and the shift duration exceeds 14 hours without prior approval, the system:
1. Caps calculated 'worked_hours' at 12.0 hours for safety to prevent payroll inflation.
2. Keeps exact actual duration in 'raw_hours' (e.g. 24.0h).
3. Auto-populates notes requesting Manager approval.

RUNNING COMMAND (24-Hour Shift: Mon 9:30 AM to Tue 9:30 AM):
curl -X POST http://127.0.0.1:8000/api/attendance/ \
  -H "Authorization: Token ca9807b61fb9affe3ab6bf02fd6dcf529b73558e" \
  -H "Content-Type: application/json" \
  -d '{
    "employee": 1,
    "check_in": "2026-09-01T09:30:00Z",
    "check_out": "2026-09-02T09:30:00Z",
    "status": "present",
    "is_manual_correction": false
  }'

EXPECTED RESPONSE (HTTP 201 Created):
{
  "id": 2,
  "employee": 1,
  "raw_hours": 24.0,
  "worked_hours": 12.0,
  "is_manual_correction": false,
  "notes": "Auto-flagged: Check-out exceeded 14 hours (24.0h). Capped at 12h pending Manager overtime approval."
}
